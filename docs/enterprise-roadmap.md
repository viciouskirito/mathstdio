# Math Studio 改进与企业化方案

规划日期：2026-09-09。当前交付版本：3.1.0。

## 产品定位与实施顺序

从教学演示扩展为可复现的数学分析工作台。优先解决错误图像和工作丢失，再引入企业身份及共享数据。延续现有 TypeScript、Canvas、Three.js、Vite 和 Vercel 部署，避免在没有明确需求时重写应用。

| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| P0：数学可靠性   | 无穷 / 非实数不入画布；极点不跨接；未定义点不插值伪造；零点必须满足实际残差；密集带保留局部观测范围；所有求值有预算；回归覆盖 `1/x`、偏移极点、`tan(x)`、取整、溢出和密集振荡 | 本次实现       |

## 本次技术决策

1. 从 UI 抽取纯采样模块，先覆盖全视口基础探测，再在每个区间内递归细分，防止单一奇点耗尽整幅图的基础采样。非等距探测降低规则采样产生的相干混叠。单函数预算为 16,000 / 32,000 次；每个区间另设预算，限制最坏开销。
2. 在预算、最小像素宽度或深度边界处，断开无法确认的线段。只对有多次方向反转且高度受限的观测显示半透明带，不跨间断合并整片矩形。有限采样仍有遗漏任意窄特征的可能，必须如实展示限制。
3. 零点分析要求实际残差接近零，拒绝仅凭符号变化把极点或跳变识别为根。视图限制坐标量级和浮点精度，网格刻度以有限数量生成；自动适配不超过合法跨度。
4. 采样缓存以表达式、范围、画布尺寸和质量为键；主题或颜色变化复用采样。当前执行仍在主线程，复杂表达式和多曲线负载由后续 Worker 阶段进一步优化。
5. 本机项目用显式字段白名单序列化，不保存密钥、AI 会话或任意导入属性。JSON 有大小限制，CSV 文本做公式注入防护，计算结果保留完整数值。
6. 草稿与手动版本分离。恢复 / 导入先留存当前版本，限制最近 20 个；存储损坏不覆盖原始数据，存储失败提示导出，多标签页写入前核对已读内容，检测到变化后暂停自动保存。这是本机防覆盖机制，不是分布式并发协议。

## P2 数据与授权设计

建议继续使用现有前端，在同一部署体系增加 API，采用托管关系型数据库与对象存储。表结构：`organizations`、`memberships`、`projects`、`project_revisions`、`audit_events`。所有项目记录包含 `organization_id`；每次读写在服务端验证身份、组织和项目角色。

角色分为管理员、编辑者、只读者；默认私有。版本记录只追加，更新项目必须带 `expected_revision`，发生冲突返回 409，保留双方修改并提供比较入口。文件和数据库查询都要执行租户级授权，不以 UI 隐藏按钮代替权限。

API 包括项目列表、创建、读取、追加版本、恢复版本、导出及审计查询。项目列表分页；导入限流、限制请求体；表达式在服务端同样校验。日志记录用户、组织、操作、对象、结果和请求 ID，不记录密钥、原始敏感表达式或 AI 提示词。

验收：跨租户越权请求全部拒绝；只读用户不能写；并发版本写入可重现冲突；删除 / 恢复留痕；备份可在隔离环境完整恢复；注销后访问失效。提供数据库迁移与可重复的集成测试后再开放团队注册。

## P3 计算工程设计

采样 Worker 接收表达式、视图与请求编号，拖拽后取消或忽略旧任务，只有最新请求可更新画布。使用 TypedArray 传递分段结果，设置内存与执行上限。低性能设备降级为均衡采样，仍保留有效工作和导出能力。

数值分析先明确有限区间、定义域和容差，输出结果及收敛 / 不收敛状态；积分跨奇点时拒绝给出未经验证的单个结果。参数扫描和数据拟合均保留输入、算法版本和参数，用于复现。3D 分段采样应在空间距离突变或未定义处拆段，不能连接跳过的点。

## P4 运营与安全

企业 AI 调用通过服务端网关保存组织密钥、设置额度与超时，并按组织授权。现有个人直连模式可以保留，但不得作为团队凭据管理方案。新增监控默认只收集版本、耗时分位数、错误码和请求 ID，避免上传用户公式。

先建立真实基线，再确定目标：交互主线程任务尽量控制在 50 ms 内；团队 API 的可用性、P95 延迟、RPO / RTO 根据实际预算和部署区域约定。配置发布回滚、数据库迁移回退策略和告警处理人。权限、SSO、配额和审计在具备后端验证前不展示为可用功能。

## 发布与回滚

先运行完整质量检查，更新并人工检查有意变化的视觉快照，再推送生产分支触发既有 Vercel 部署。发布后核对 `build-info.json` 的版本和提交，检查首页及静态资源 HTTP 响应。若构建或验证失败，修复后重新验证；线上故障回滚到上一成功部署。Git 集成行为参见 [Vercel 官方文档](https://vercel.com/docs/git)。
